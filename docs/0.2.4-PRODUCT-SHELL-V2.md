# Personal Agent Rus 0.2.4 — Product Shell v2

0.2.4 closes the Foundation UI gap discovered on the Windows reference host: a healthy backend was serving a smoke-grade frontend and stale browser assets could survive an in-place upgrade.

## User shell

Mandatory product-shell behaviors:

- persistent conversation sidebar;
- New Chat;
- conversation search;
- rename/delete current conversation;
- clear current/all conversations with explicit confirmation;
- current-chat Markdown export and all-chat JSON export;
- copy and regenerate actions;
- safe Markdown/code rendering without `innerHTML`;
- mode selector (Auto/Fast/Smart) without exposing model IDs;
- Settings modal with Data/Capabilities/Admin navigation;
- explicit authenticated Administration entry;
- honest preview controls for capabilities that are not implemented yet;
- responsive mobile drawer and composer.

## Cache/version contract

The Core emits `Cache-Control: no-store, max-age=0, must-revalidate` for product pages/assets. HTML references versioned assets (`?v=0.2.4`). USER and ADMIN UI compare their semantic version to Core and perform at most one automatic reload on mismatch. Persistent mismatch becomes a visible repair warning/error instead of silently combining old UI with a new backend.

## Rus edition language contract

The system prompt requires Russian by default. If a short Russian/neutral request receives a non-Cyrillic response from a small bootstrap model, Core retries once with an explicit Russian-only system constraint. The deterministic integration fixture proves the retry path; the real-model result remains an authoritative Windows acceptance item.

## Capability honesty

WEB/files/code/media controls that are not implemented are visibly marked planned. A URL/news request cannot fall through to plain LLM chat while WEB is unavailable. It returns `capability_unavailable` and USER receives a product-level explanation rather than fabricated site content.
