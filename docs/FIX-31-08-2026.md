План действий и методы решения

1. Первая волна: исправления, которые должны попасть сразу

- Баланс и профиль:
  Метод: перестать показывать пустые или неподключённые блоки как готовую коммерческую функцию. На странице аккаунта выводить фактический quota snapshot, usage и честные статусы по YooMoney, промокодам и темам, пока серверная автоматизация не подключена.
- Кнопка выхода:
  Метод: дублировать logout в левом меню для обычного пользователя, а не только в личном кабинете или admin-сценарии.
- Юридические страницы:
  Метод: добавить прямые маршруты `/terms`, `/privacy`, `/cookies`, `/disclaimer` на соответствующие static html, чтобы не было 404.
- Время в чатах:
  Метод: вместо относительного вида вроде `6 мин` показывать фактическое время последнего запроса за текущий день и дату для старых диалогов.
- Локальный/VPS copy:
  Метод: в UI опираться на `runtime_profile` и показывать "Свой сервер" / `Self-hosted server`, а не везде писать "локальный".
- Возможности:
  Метод: убрать ложный статус `Запланировано` у доступных модулей, развести состояния `ready`, `degraded`, `admin`, `planned`, `plan locked`.
- Новый проект:
  Метод: после создания проекта сразу предлагать перенести текущий диалог и активировать новый проект в боковой панели.
- Архив:
  Метод: вынести архив в левое меню как явный раздел, а не прятать доступ только в `...`.
- Мобильная и форменная вёрстка аккаунта:
  Метод: ужать iframe YooMoney, добавить заметки и выровнять account-блоки для узких экранов.
- Линия 76 из замечаний:
  Метод: пройти account/settings/login/register и убрать видимость неподключённых действий, добавить честные пояснения и выровнять тексты/формы.

2. Вторая волна: доработка UX и пользовательских настроек

- Обучение только при регистрации:
  Метод: не запускать tour автоматически для всех новых сессий. Взводить onboarding-флаг только после успешной регистрации и давать пользователю право сразу пропустить обучение.
- Пользовательские предпочтения:
  Метод: добавить в настройки сохраняемое поле личных предпочтений и прокидывать его в системные инструкции ответа как мягкий персональный профиль.
- Неочевидность файлов:
  Метод: в onboarding/help и в настройках явно подсветить, что файлы можно и загружать, и создавать прямо из workspace-панели.
- Переводы:
  Метод: после хотфиксов пройти `app.js`, `auth.js`, account/login/register/admin страницы и убрать оставшиеся не локализованные строки.

3. Третья волна: серверные фичи, которых сейчас реально нет

- Подтверждение почты:
  Метод: завести таблицу verification tokens, expiry, resend-limit, SMTP-конфиг и переход пользователя в `pending_email_verification` до подтверждения.
- Восстановление пароля:
  Метод: отдельный reset token flow с TTL, одноразовостью токена, audit log и invalidation всех старых токенов после смены пароля.
- Автозачисление платежей:
  Метод: webhook от платёжного провайдера, таблица платежей, идемпотентная обработка статусов, ledger по пользователю, привязка к subscription/balance.
- Промокоды:
  Метод: серверная сущность promo code с лимитами активаций, сроком жизни, типом бонуса и аудитом применения.
- Платные темы:
  Метод: отделить встроенные темы от покупаемых, хранить entitlement по теме и не показывать кнопку покупки, пока нет server-side подтверждения.

4. Четвёртая волна: admin и поисковый контур

- Расширение перечня сайтов:
  Метод: упростить admin UI для `site_profiles`: быстрые пресеты, bulk add domains, импорт списком и понятные категории по рынку РФ.
- SEO и индексирование:
  Метод: отдельно внедрить on-page SEO пакет по примеру `AgriciDaniel/on-page-seo`, затем проверить sitemap, meta, canonical, robots, structured data и контентные посадочные страницы.

5. Пятая волна: инфраструктура и производительность

- Медленный ответ Qwen 0.6 на VPS:
  Метод: снять замеры по шагам `queue -> prompt build -> inference -> postprocess`, затем решать через меньшую модель по умолчанию, прогрев, KV-cache, изменение route policy или перенос части трафика на remote provider.
- Amnezia / routing:
  Метод: сделать отдельный admin flow с токеном/профилем, валидацией конфига и тестом маршрута из панели, без ручной правки нескольких файлов.
- ChatGPT / DeepSeek / без VPN:
  Метод: разделить provider onboarding на BYOK и platform-managed, для каждого показать ограничения РФ, схему ключа, health-check и fallback policy.
