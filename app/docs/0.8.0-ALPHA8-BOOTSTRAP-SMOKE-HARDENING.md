# 0.8.0-alpha.8 — Bootstrap Smoke Hardening

## Windows evidence that triggered this slice

On the reference Windows PC, `alpha.7` reached `/api/admin/inference/smoke` successfully (`HTTP 200`) after about 43.8 seconds, then failed the logical assertion because the response reported no final content.

## Root cause

The bootstrap model is Qwen3 and supports a separate thinking channel. With a tiny generation budget, a thinking-capable model can spend the budget on `message.thinking` and leave `message.content` empty. The old smoke used 16 tokens and did not explicitly disable thinking.

## Fix

- bootstrap smoke sets `think=false`;
- output budget increased from 16 to 32 tokens while still remaining tiny;
- prompt asks for exact `PAR_OK`;
- normal user inference is unchanged and may still use provider/model thinking behavior;
- HTTP-200 logical failure now reports model, reason, content length and native timing before failing;
- deterministic fake Ollama reproduces the thinking-only edge case, and Core API acceptance verifies the smoke actually sends `think=false`.

## Required Windows evidence

`RUN-FIRST.cmd` / `VERIFY.cmd` must show:

```text
HTTP stage=bootstrap-inference ... status=200
INFERENCE bootstrap model=qwen3:0.6b ok=True reason=ok content_length=...
... load_ms=... prompt_eval_ms=... generation_ms=... tokens_per_sec=...
[PASS] Runtime verification passed ...
```

If the endpoint still returns `ok=false`, the new log is sufficient to distinguish empty final content from transport/model-load failures.
