# 0.2.4 — Product Shell v1 + Capability Honesty

This foundation hotfix closes two user-visible defects discovered on the Windows reference host:

1. the previous browser UI was a smoke shell rather than a product-grade Personal Agent surface;
2. URL/site requests were routed into plain local chat even though WEB was not implemented, allowing the model to fabricate site/news content.

## Product Shell v1

USER now receives:

- Open-WebUI-like two-column shell without exposing implementation internals;
- conversation sidebar and New Chat;
- persisted multiple local conversations with migration from the legacy single-chat key;
- top mode switcher (Auto/Fast/Smart);
- runtime status;
- richer message layout;
- persistent composer;
- honest visible capability state;
- discoverable authenticated Administration entry;
- mobile drawer layout.

ADMIN now receives a dedicated dashboard with Overview, Routing, Models and System tabs. Technical model IDs remain behind admin authentication.

## Capability honesty invariant

Until WEB ships, a request containing an external URL/domain is intercepted by Core and returns structured `409 capability_unavailable` instead of being sent to the LLM as ordinary chat.

The UI renders this as an explicit capability notice. Therefore requests such as `выдай новости с https://dtf.ru/` cannot produce fabricated site content in foundation builds.

## Rus language default

The Rus edition system prompt now explicitly answers in Russian by default, including short neutral messages, unless the user explicitly requests another language.

## Regression evidence

Mandatory gates added:

- `FND-PRODUCT-SHELL-001`
- `FND-CAPABILITY-HONESTY-001`
