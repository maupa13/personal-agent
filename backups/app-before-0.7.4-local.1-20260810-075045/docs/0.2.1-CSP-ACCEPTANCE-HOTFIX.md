# 0.2.1 — Strict-CSP browser acceptance hotfix

## Failure reproduced on reference Windows host

The 0.2.0 runtime passed startup, readiness, real inference, restart and VERIFY. FULL-ACCEPTANCE failed because the Playwright suite used string-based `wait_for_function()` polling. Production correctly sets strict CSP with `script-src 'self'` and without `unsafe-eval`, so the test itself violated the product security contract.

## Root-cause rule

Do not weaken CSP. Fix the whole test anti-pattern and add regression coverage.

## Changes

- Removed all `wait_for_function()` usage from live and offline browser suites.
- Added a static regression guard against `wait_for_function`/eval-based live polling.
- Replaced waits with locators and Python-side condition polling.
- Live desktop journey now checks all three modes, real chat, XSS-as-text and refresh persistence.
- Live mobile journey now performs a real chat in addition to layout checks.
- Live admin journey checks bad/good authentication, routing persistence, async model-pull UI and reload persistence.
- Backend-derived mode labels now render through DOM nodes + `textContent`, not backend-derived `innerHTML`.
- Browser failures persist screenshot, HTML, console, page-error, network-error and context evidence.
- Added `tests/acceptance-registry.json` and included the master v2 execution contract in `docs/`.

## Environment evidence

The build environment passes static/API/offline Chromium gates. Its Chromium is administratively blocked from local HTTP navigation, so the live-CSP gate is recorded `BLOCKED_ENVIRONMENT` here and remains mandatory on the Windows reference host.
