# 0.8.0-alpha.6 — Search Integrity, Result Cards, Debug Observability

## Зачем этот slice

Alpha.6 закрывает два дефекта реального Windows/user journey:

1. запрос к конкретному сайту мог получить evidence с другого домена;
2. lifecycle/API ошибки показывали слишком мало данных для быстрой диагностики.

Дополнительно пользовательские списочные результаты получили адаптивные карточки, а Admin — управляемую политику источников и readiness-контур ЮKassa.

## Source Integrity

Явный домен пользователя (`dtf.ru`, `https://dtf.ru/...`, `site:dtf.ru`) является authoritative scope.

При strict-domain запросе:

- search строится с `site:<domain>`;
- unrelated evidence отбрасывается до LLM synthesis;
- site profile не может расширить scope на другой домен;
- если источник недоступен, продукт сообщает об этом, а не подменяет его другим сайтом;
- поиск по другим сайтам возможен только как явно разрешённый отдельный шаг/Research policy.

Глобальные Admin preferred domains являются boost. Blocked domains являются hard policy. Явно запрошенный домен не обходится молча.

## Result Cards

Structured evidence преобразуется в безопасные cards типов:

- news;
- product;
- real_estate;
- procurement;
- generic source.

Карточка может показать только данные, реально присутствующие в evidence: title, source/domain, verified summary, published date, price/parameters when supplied by source. LLM не генерирует фиктивную цену для card metadata.

CSS использует адаптивную сетку, `content-visibility`, лёгкие transitions и полностью отключает необязательную анимацию при `prefers-reduced-motion`.

## Debug observability

Каждый ответ хранит безопасные timing/trace metadata:

- total `duration_ms`;
- routing;
- web/search;
- inference;
- source count;
- request_id;
- correlation_id.

USER видит время выполнения и понятный summary. OWNER/ADMIN в debug mode может увидеть дополнительные безопасные timings/trace, но USER surface не получает model/provider technical IDs.

Windows lifecycle HTTP failure пишет:

- stage;
- method;
- endpoint;
- HTTP status;
- duration;
- request_id;
- correlation_id;
- sanitized response body/error.

## Admin: Search Policy

В alpha.6 реально подключён только SearXNG adapter. Yandex/Google не отображаются как working adapters до фактической реализации.

Admin может менять:

- maximum source count для general/news/research;
- preferred domains;
- blocked domains;
- site profiles/acquisition order.

## Payment readiness

Admin → Subscriptions & Usage → YooKassa показывает readiness checklist:

1. Shop ID;
2. Secret Key stored;
3. public HTTPS URL;
4. webhook actually observed;
5. successful payment actually re-verified.

Secret Key не возвращается из API. `production_ready` не становится true только от заполнения формы.

## Не заявлено как PASS

- Yandex Search API adapter;
- Google Search API adapter;
- live DTF availability;
- live YooKassa merchant flow;
- PostgreSQL canonical server runtime;
- RU/global egress routing.
